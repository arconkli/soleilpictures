# Walking through buying Team (T1b) — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** On the preview site, Settings › Preview › Team plan › "Walk through buying it" opens the real `/pricing` page with a third card, Team (seat picker, "Start a Team trial", "Talk to us"); the trial button opens the team setup at `/team/new` in the workspace-setup look (team name and which workspaces move in → seats and yearly/monthly → where Stripe would take the card → bring your people → done); "Open the team page" lands back in the app with the test team, under the name you typed, on its page. Look only: no checkout, no email, nothing saved on the server.

**Architecture:** The pricing view (`boards/src/auth/PricingPageView.jsx`, shared by the signed-in and signed-out pages) takes an optional `teamCard` prop and lazy-loads the card only when it is passed; only the signed-in container (`PricingPage.jsx`) passes it, and only while the team preview is on (`teamPreviewAvailable() && readTeamPreview()`). The crawlable pricing HTML, `/pricing.md`, `billingCopy.js` and the SEO probe rows never see it. `/team/new` is a branch in `boards/src/auth/TierRouter.jsx` (signed-in only, preview only) rendering a lazy `TeamSetup` that reuses the workspace setup's frame and CSS (`components/setup/setup.css`, `Behind` from `WorkspaceSetup.jsx`). The way back is two small preview keys in `lib/teamPreview.js`: the typed name (localStorage) and "open the team page once on boot" (sessionStorage).

**Tech stack:** as `docs/superpowers/plans/2026-10-21-team-page-preview.md` (React 18, plain CSS with the app's tokens, Phosphor regular icons, `node --test`, Playwright).
